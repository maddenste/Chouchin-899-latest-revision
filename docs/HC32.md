# HC32 movement firmware

The controller is **HDSC HC32L130J8TA**, not the older board's MM32.
V15 is a patch of the original vendor binary, not a complete source rewrite.
Patch sources and original dumps are retained privately; distribution rights
for the underlying vendor firmware remain unresolved.

## Candidate

HC32 V15, 65,536 bytes, SHA-256:

`B1D557505163B973FD59B20AA80246DA853F2F4A3D3AC555D53715180C533A60`

The owner installed V15 before Wi-Fi R13/R14 testing. The documented current
pair is **V15 + Wi-Fi v2.0 R16**. The owner reconfirmed V15 is installed. See [TESTING.md](TESTING.md) for actual observed coverage.

## SWD debug connection

HC32 **PA13 = SWDIO**, **PA14 = SWCLK**; connect common ground and follow the
probe's target-voltage requirements. These are HC32 pins, not the TXW UART
pins with the same names. The programmer is a CMSIS-DAP / DAPLink ARM JTAG/SWD
probe. No photograph is available; exact pin-label connections are being
confirmed by the owner in the wiring table; no physical header orientation is inferred.

The local device project uses Keil and the
**HDSC.HC32L130.1.0.1** pack, including **FlashHC32L130_64K.FLM**.
Select the exact HC32 device, ARM SWD, and a conservative 100 kHz initial
debug clock. Confirm the correct 64 KiB flash algorithm and candidate path
before any SWD operation. These project settings do not describe the owner's
actual UART boot-mode installation.

## Original firmware backup — Keil µVision 5 over SWD

The owner confirmed the original HC32 firmware backup was read using
**Keil µVision 5**, with DAPLink **TMS/IO to DIO, TCK/CK to CLK and GND to
common board ground**. This was not an XHSC UART read.

### Read-only Keil setup

The archived read-only project confirms these settings:

| Setting | Value |
| --- | --- |
| Device | HDSC HC32L130J8TA |
| Device pack | HDSC.HC32L130.1.0.1 |
| Debug adapter | CMSIS-DAP (CMSIS_AGDI.dll) |
| Interface / initial clock | SWD / 100 kHz |
| Flash address / size | 0x00000000 / 0x10000 (64 KiB) |
| RAM address / size | 0x20000000 / 0x2000 (8 KiB) |
| Load Application at Startup | Disabled in the target debugger |
| Update Target before Debugging | Disabled |
| Debug initialization file | None |

Install Keil µVision 5 and the device pack separately. Create a project for
this exact device, without adding application/startup code. Under Options for
Target → Debug, select the CMSIS-DAP adapter and disable Load Application at
Startup. In its Settings, select SWD at 100 kHz and your connected probe.
Under Utilities, disable Update Target before Debugging. Also disable
Run to main() for a backup-only session; the archived project retained that
checkbox, but it is unnecessary when no application is loaded.

Connect the confirmed SWD wires, power the board and start a debug session
without building or downloading firmware. Open View → Command Window.
Do not use Flash Download, erase, unlock or a flash algorithm to obtain a backup.
Attaching may halt/reset the running controller: this is flash-read-only,
not a guarantee of zero runtime disturbance.

The saved session records identify **SAVE commands entered in Keil's Command
pane**, rather than a standalone PowerShell read script. On 24 September 2026,
the read was repeated in five chunks spanning the complete 64 KiB flash.
The historical commands below use a relative output filename; choose a new
output location explicitly (replace each filename with a new absolute path
without spaces if needed). Do not overwrite an existing backup.

```text
SAVE HC32L130_recheck_00000000-000043FF.hex 0x00000000,0x000043FF
SAVE HC32L130_recheck_00004400-0000B3FF.hex 0x00004400,0x0000B3FF
SAVE HC32L130_recheck_0000B400-0000B5FF.hex 0x0000B400,0x0000B5FF
SAVE HC32L130_recheck_0000B600-0000B7FF.hex 0x0000B600,0x0000B7FF
SAVE HC32L130_recheck_0000B800-0000FFFF.hex 0x0000B800,0x0000FFFF
```

Local notes record valid Intel HEX checksums, 65,536 distinct bytes with no
gaps or overlaps, and an assembled image matching the earlier backup.
The assembled original SHA-256 is
`7F464A7EF98DBFC5FE41A3B2EA14E16EF964885490D7C8276CE34DC4D25C433F`.
This is a historical procedure, not a newly repeated hardware test.
Do not substitute an erase, Download or protection-unlock operation for
a read-only backup. Keil's Download action writes firmware to the target.

### Validate the exported backup

The included Python helper checks Intel HEX checksums, rejects gaps/overlaps
and assembles exactly 65,536 bytes. It never connects to a programmer.
Supply your five actual export filenames:

```powershell
python .\tools\verify_hc32_backup.py chunk1.hex chunk2.hex chunk3.hex chunk4.hex chunk5.hex --output original-hc32.bin
```

The output must not already exist. Keep the original HEX files and hash
privately. Different factory firmware can legitimately have a different hash;
do not require another owner's original hash to match yours.

## Firmware installation — UART boot mode

The owner confirmed firmware programming used **U_TX to DIO, U_RX to CLK,
and GND to common board ground**, with the HC32 board BOOT pad held at 3.3 V
from the bench supply. The bench supply also powered the clock board itself.
Programmer 3V3/5V and nRST were not connected.
SWD used only TMS/IO to DIO, TCK/CK to CLK and common ground, for debugging
and the original Keil backup.

The programming tool is **XHSC MCU Programmer V2.23**, obtained separately.
The owner supplied a screenshot of the working settings. Windows file metadata
reports 1.0.0.0, but the application's displayed version is V2.23.

The displayed family selector includes HC32F030, but this project's actual
movement chip is HC32L130J8TA. This is not a compatibility claim for HC32F030.
Chip Erase is destructive: retain a verified original backup before executing
the operation. Do not select a Wi-Fi image in this tool.

The local configuration selects the V15 HEX, full-duplex serial communication,
chip erase, program and verify, with encryption/protection options disabled.
Its saved COM port is machine-specific; do not copy COM1 as a universal setting.
Numeric device/crystal indices are not documented as portable UI selections.
The latest local log on 1 October 2026 reports programming and verification
success. This is distinct from TXW write-only programming, which had no readback.

### Enter UART programming mode

The owner confirmed this sequence:

1. With the board off, connect U_TX to DIO, U_RX to CLK and common ground.
   Leave DAPLink USB unplugged. Do not connect programmer 3V3/5V or nRST.
2. Hold BOOT at 3.3 V from the bench supply **before powering on the board**.
3. Power the clock board from the bench supply, then plug the DAPLink into USB. The owner reported
   this order was necessary. Keep BOOT high throughout UART programming.
4. Select the now-enumerated programmer COM port in XHSC V2.23 and use the
   settings above.
   For writing V15, the selected operation is Chip Erase with Erase, Program
   and Verify enabled. Preserve an original backup before any erase.
5. Wait for the operation and verification to complete; do not interrupt power.
6. Switch board power off, disconnect BOOT from the bench supply's 3.3 V,
   then power the board on normally. This sequence was confirmed by the owner.

Do not leave BOOT forced high for ordinary clock operation.
Use the confirmed family selection above for this HC32L130J8TA board;
do not enable encryption or protection unintentionally.

Obtain an original read-only backup first. Protection unlock/erase is a separate,
potentially destructive operation; do not assume it is necessary or authorised.
There is no separately validated public one-command HC32 installer in this draft.

The private local archive includes the actual Keil project files used, and
historical patch sources. Those sources still need a reproducible, portable
HC32 build audit before a from-source public HC32 build can be promised.

## Changes relevant to the Wi-Fi firmware

- Parser accepts the two ASCII selector digits after the ordinary +TIME fields.
- Overnight restart fix retains the original battery-voltage checks.
- Saving mode 2 lets the seconds hand reach 12, then remain parked indefinitely.
- Daily wake accepts minute precision; the Wi-Fi UI exposes ten-minute increments.
- Temporary DST wake can use minute precision without replacing the saved daily time.

Do not substitute an old V11 candidate: its feature set is not the current V15
release pairing. No HC32 flashing is performed by any TXW script.
